# 7.4 Q-learning: learn a greedy target from exploratory behavior

[Chapter 7 PDF, pages 16–21](../../../3%20-%20Chapter%207%20Temporal-Difference%20Methods.pdf#page=16), printed pages 140–145, covers 7.4.1–7.4.4. Prerequisites: Sarsa and the Bellman optimality equation.

## 7.4.1 Replace the sampled next action by a maximum

At a nonterminal transition $(S_t,A_t,R_{t+1},S_{t+1})$, tabular Q-learning uses

$$Y_t=R_{t+1}+\gamma\max_{a'\in\mathcal A(S_{t+1})}Q_t(S_{t+1},a'),$$

$$Q_{t+1}(S_t,A_t)=Q_t(S_t,A_t)+\alpha_t(S_t,A_t)\,[Y_t-Q_t(S_t,A_t)].$$

Other entries stay unchanged in that update. When $S_{t+1}$ is terminal, use $Y_t=R_{t+1}$: there is no next decision to bootstrap. The environment determines the sampled next state; the maximum compares actions *at that observed state*. Taking the conditional expectation of the target with the true values leads to the action-value Bellman optimality equation.

Suppose $Q_t(S_t,A_t)=2$, the observed reward is $1$, $\gamma=0.5$, and the successor action estimates are $4$ and $2$. The target is $1+0.5(4)=3$. With $\alpha=0.1$, the updated entry is $2+0.1(3-2)=2.1$. In Sarsa, if the behavior actually selects the action valued $2$ at that successor, its target instead is $1+0.5(2)=2$.

## 7.4.2 Which policy generated the data?

The **behavior policy** chooses actions that produce transitions. The **target policy** describes the decisions whose values the update aims to improve. For the Q-learning backup, the target decision is greedy with respect to the current $Q$; the behavior can be exploratory and may select a different successor action. The greedy policy evolves as $Q$ changes. One-step Sarsa instead uses the actual next behavior action, so its usual fixed-policy version evaluates that same policy.

The source also calls its Algorithm 7.2 an “on-policy version” because an $\epsilon$-greedy policy both generates actions and is reported as the policy being updated. Its backup still takes a **max**, so it targets the greedy Bellman optimality operator rather than the Bellman evaluation operator of that exploratory policy. When comparing implementations, specify both the behavior rule and the backup; these reveal the operational distinction.

## 7.4.3 Coverage is a separate requirement

Consider states Start and Hidden. At Start, action Stay always returns to Start; action Enter reaches Hidden. If the behavior always chooses Stay, no transition from Hidden is ever observed. The max in a Q-learning target cannot create information about Hidden's rewards or correct its unvisited entries. Even randomization among actions at visited states does not reach a state that is impossible to reach from the start under the dynamics; an early absorbing trap can also prevent later visits. Starting-state distribution, reachability, and behavior all matter.

For the classical finite, stationary, discounted tabular setting, a standard convergence result requires bounded rewards, $0\le\gamma<1$, every relevant state–action pair to be visited infinitely often, and per-pair step sizes satisfying

$$\sum_{k=1}^{\infty}\alpha_k(s,a)=\infty,\qquad \sum_{k=1}^{\infty}\alpha_k(s,a)^2<\infty.$$

Here $k$ counts updates *to that pair*. Under the usual stochastic approximation assumptions, $Q$ converges to $q^*$ almost surely. The conditions concern the actual visitation process, not merely the name “$\epsilon$-greedy.” A fixed positive learning rate is useful for adapting to change, but does not satisfy the square-summability condition; persistent sampling noise can leave the estimate fluctuating. Finite data, function approximation, or changing environments need their own analysis.

## 7.4.4 Read the source examples

In Figure 7.3, the book uses an $\epsilon$-greedy behavior to seek a path from a given start. Figures 7.4–7.5 instead compare behavior policies and their resulting grid-world learning curves. Their exploration patterns and initialization influence those runs; the curves help interpret the role of experience, while the conditions above state the scope of the convergence result.

Online/offline describes *when* data are collected relative to updates; on/off-policy describes the relationship between the behavior and target in an update. These are distinct axes: Q-learning can process transitions as they arrive or learn from stored transitions when the needed coverage and assumptions hold.
