# 9.1 Represent a policy with parameters

**Source:** [Chapter 9 PDF, pages 2–3](../../../3%20-%20Chapter%209%20Policy%20Gradient%20Methods.pdf#page=2), printed pages 192–193. This companion introduces a two-state example used through [Section 9.3](09-03.md).

A tabular policy stores probabilities separately for each state and action. A parameterized policy computes them using a function $\pi_\theta(a\mid s)$: change the parameter $\theta$, and the action probabilities change. The parameter can be a scalar, a vector of weights, or the weights of a neural network.

## A continuing two-room task

An agent is in room $A$ or $B$. At every step it chooses **stay** or **switch**:

| Current state | Action | Next state | Immediate reward |
| --- | --- | --- | --- |
| $A$ | stay | $A$ | $1$ |
| $A$ | switch | $B$ | $0$ |
| $B$ | stay | $B$ | $0$ |
| $B$ | switch | $A$ | $2$ |

Let the policy use the same switching probability $p$ in both rooms:

$$
p=\sigma(\theta)=\frac{e^\theta}{1+e^\theta},\quad
\pi_\theta(\text{switch}\mid s)=p,\quad
\pi_\theta(\text{stay}\mid s)=1-p,\qquad s\in\{A,B\}.
$$

At $\theta=0$, $p=1/2$, so each action has probability $1/2$ in each room. At $\theta=\log 3$, $p=3/4$, so switching has probability $3/4$ in **both** rooms. One parameter affects both rows: this is parameter sharing. It can support generalization, but this particular policy class cannot represent, for example, switching with probability $0.9$ in $A$ and $0.1$ in $B$. A table with separate entries could represent that policy.

The values $0<p<1$ for finite $\theta$ and $(1-p)+p=1$ make each row a valid probability distribution. The policy determines how actions are sampled; it does not itself state how much future return an action produces. A separate action-value function $q_{\pi_\theta}(s,a)$ answers the latter question.

## Softmax turns scores into probabilities

For a finite legal action set, a common parameterization uses scores $h_\theta(s,a)$:

$$
\pi_\theta(a\mid s)
=\frac{\exp h_\theta(s,a)}
{\sum_{b\in\mathcal A(s)}\exp h_\theta(s,b)}.
$$

Each exponential is positive, and division by the sum makes the probabilities add to one. In our example take $h_\theta(s,\text{switch})=\theta$ and $h_\theta(s,\text{stay})=0$ in both rooms; the softmax then gives the sigmoid policy above. A different set of features or scores can represent different behaviors.

A policy function may take $(s,a)$ and output one probability, or take $s$ and output a distribution over all legal actions, as in the book's Figure 9.2. It is the choice of function and parameters—not merely the use of a function—that determines what policies can be represented.

## What should the parameter maximize?

Given a scalar policy-quality objective $J(\theta)$, gradient ascent takes the form

$$
\theta_{k+1}=\theta_k+\alpha\nabla_\theta J(\theta_k).
$$

Here $k$ counts optimization updates, $\alpha>0$ is the step size, and the gradient points in the direction of the local increase of the chosen objective. We first need to define $J$: the return from room $A$ and the long-run reward per step are different questions. [Section 9.2](09-02.md) makes that choice explicit.
