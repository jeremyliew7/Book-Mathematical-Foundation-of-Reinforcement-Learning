# 4.5 Q&A

Use these questions to connect the chapter's algorithms before moving on. The questions and explanations reorganize the source Q&A; for calculations and proofs, return to the earlier sections.

### Is every vector called a value an exact policy value?

No. For a fixed policy $\pi$, its exact value $v_\pi$ satisfies $v_\pi=T_\pi v_\pi$. An intermediate value-iteration vector or a truncated evaluation vector can be a useful estimate without satisfying that equation. To check a proposed vector for a particular policy, calculate its Bellman residual $v-T_\pi v$; zero residual identifies the fixed point in this finite discounted setting. A finite calculation can happen to reach that fixed point exactly.

### Why do we evaluate before changing the policy?

The value of the current policy captures the long-term consequences of continuing it. A greedy improvement uses those values to compare taking each action **once** and then continuing the old policy. After updating actions in all states, evaluating the new policy reveals the return from continuing the new choices. The worked example in [Section 4.2](04-02.md) shows why those two quantities can be very different.

### Does a greedy policy have to stop changing when values converge?

If several actions have equal maximizing lookahead, different action choices can represent equally valued policies. A consistent tie rule, such as keeping the current maximizing action, makes stable policy representation possible. The discounted value-convergence result is about the value; claims about the exact sequence of action labels need tie handling as well.

### What is the role of the model?

In the chapter's dynamic programming, a supplied model provides transition probabilities and expected rewards for computing backups. The book contrasts this with model-free RL, which learns from experience without first estimating a transition model. Model-based RL can instead estimate a model from experience and use it during learning. These are families of methods; how data are collected and how a learned model is used depends on the algorithm.

### What does generalized policy iteration mean?

It is the pattern in which policy improvement uses value information and value estimation responds to the policy. Evaluation may be exact or approximate, and improvement need not be organized identically in every algorithm. The chapter's three methods are useful cases for seeing this interaction.

1. **Identify.** A program reports $v=(3,4)$ for a policy. What additional calculation checks whether it is the policy's exact value?

   *Hint:* use the fixed-policy Bellman equation at both states.
2. **Apply.** An agent fits a transition model from observed transitions and uses simulated trajectories from that model to improve a policy. Which steps use real data and which depend on the fitted model?

   *Hint:* trace the source of each trajectory.

   *Hint:* find where $\gamma<1$ makes a repeated error term shrink.
