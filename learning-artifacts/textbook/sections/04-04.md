# 4.4 Summary

A known model tells us the possible immediate rewards and next states for each action. Chapter 4 asks how to use that model to find a good policy when the goal is long-term discounted reward. The three methods share an exchange between **estimating values** and **choosing actions**. They differ in how much they evaluate one policy before choosing again.

| Method | Value step | Policy step |
| --- | --- | --- |
| Value iteration | Apply one optimality backup $v_{k+1}=Tv_k$ | Choose a maximizing action for each state from the current lookahead. |
| Policy iteration | Solve the fixed-policy Bellman equation for $v_{\pi_k}$ | Choose a policy greedy with respect to that exact value. |
| Truncated policy iteration | Apply a finite number of fixed-policy backups to the current estimate. | Improve greedily using the resulting estimate. |

For example, with aligned initial value and greedy choice, the Figure 4.3 example in [Section 4.3](04-03.md) gives $(-7.1,-7.1)$ after one fixed-policy backup, $(-5.39,-5.39)$ after two, and $(10,10)$ at exact evaluation. One backup produces the same first value update as value iteration; the evaluation limit gives policy iteration's exact value step. The initialization and chosen greedy policy must match for this comparison.

**Generalized policy iteration** names the broader interaction: a value estimate informs policy improvement, while the policy influences what value is evaluated or estimated next. It is a perspective shared by many algorithms, rather than a single prescription for the number of updates.

The chapter's dynamic programming methods calculate expectations from the supplied transition and reward model. The next chapter moves toward estimating returns from experience, opening the way to learning when the model is unavailable.

## Try it yourself

1. **Recognize.** Which method in the table solves the current policy's Bellman equation before improvement? Which makes one optimality backup?

   *Hint:* follow the value step in each row.
2. **Apply.** Suppose a fixed policy produces reward $1$ forever in a one-state MDP with $\gamma=0.5$. Starting from $0$, calculate two evaluation backups and its exact value.

   *Hint:* each backup is immediate reward plus half the previous estimate; the exact value is a fixed point.
3. **Reason about cost.** If two implementations reach the same desired accuracy, what would you measure before choosing how many evaluation backups to perform per policy update?

   *Hint:* consider both cost per update and the number of updates.
